# P13 — 多头期权记账（Long Options Ledger）

> 状态：设计草案 · 范围已确认（全量策略）· 待开发确认 · 2026-11-20
> 前置：[P12 降本扫描器](P12-cost-reduction-scanner.md)
> 目的：让账本记录**买入期权**，从而支持领口、保护性 Put、股票修复、比率/日历价差等策略。

## 0. 一句话

当前账本只会记账「卖出期权」。要支持需要买入腿的策略，必须先让 `wheel-core` 原生理解多头期权；扫描器不能用一个假的多头腿绕过账本，否则方案与账本会分叉。

---

## 1. 为什么必须改账本

降本扫描器推荐的策略里，一半以上需要买入期权：

| 策略 | 缺失的腿 | 不记账的后果 |
|---|---|---|
| 保护性 Put | 买 Put | 保险费与最大亏损无法进入成本 |
| 领口 Collar | 买 Put | 封顶封底后的实际盈亏无法核对 |
| 海鸥 | 买 Put | 卖 Put 补贴的部分无法计算 |
| 股票修复 | 买 Call | 修复成本与行权后的持股成本无法记录 |
| 比率/反向比率 | 买 Call | 比例腿的盈亏无法归因 |
| 日历/对角 | 买远月 | 两条腿的时间价值无法分别结算 |
| 合成多头/空头 | 买 Call/Put | 无法表示替代持股或锁定退出 |

结论：**先补多头期权记账，再开放这些策略**。扫描器的腿模型可以同时支持 Long/Short，但只有当账本能记录时，才允许「记一笔」。

---

## 2. 范围

### 2.1 v1 做

- 买入开仓（Buy to Open）、卖出平仓（Sell to Close）、到期作废、行权（Exercise）。
- 单腿与多腿：多腿就是同一账户、同一标的下的一组期权事件，不引入「组合」实体。
- 多头 Call 行权买入股票；多头 Put 行权卖出股票。
- 拆股 / 合股同时调整多头合约的行权价与每手股数。
- 录入、台账、持仓、到期中心、报表、CSV 导入全部支持方向。
- 旧账本零迁移：旧事件重放结果逐分不变。
- **已确认的策略范围**：领口 / 保护性 Put / 海鸥、股票修复 / 比率价差、日历 / 对角 / 合成。PMCC 与合成多空按「替代持股 / 锁定退出」定位，不与正股叠加。

### 2.2 v1 不做

- 组合保证金、券商风控、自动行权、指数现金结算。
- 期权做市/借券、证券借贷、税务批次。
- 跨账户组合识别（A 账户多头、B 账户空头不会自动配对）。
- 期权历史报价与逐日盯市（只做「到期作废」最坏口径 + 可选最新链估值）。


## 4. 会计口径

### 4.1 符号

- `S` 持股数；`C` 股票成本总额；`PR` 空头已落袋净权利金；`PO` 空头未平仓净权利金；`D` 计入口径分红。
- `LP` 多头已实现净盈亏（正数盈利，负数亏损）；`LO` 未平仓多头成本（正数）。
- `V` 未平仓多头的当前市值（可选，用最新期权链估算）。

### 4.2 成本三轨

```
A  = C / S
B  = (C − PR − LP − D) / S
C′ = (C − PR − PO − LP + LO − D) / S
```

解释：

- **B**：多头已实现盈亏进入成本。买 Put 到期作废，`LP` 变成负数，B 上升（保险费是成本）；买 Call 平仓获利，`LP` 为正，B 下降。
- **C′**：假设**空头全部到期作废（权利金保留）、多头全部到期作废（成本损失）**的最坏口径。因此未平仓多头把 `LO` 加回成本。
- **含市值成本**（可选展示）：`(C − PR − PO − LP − V − D) / S`，即假设现在按中间价平掉多头。仅用于参考，不进入账本。

### 4.3 盈亏与现金流

```
战役已实现盈亏 = share_pnl + PR + LP + D + adjustments
账户现金       = 全部事件现金流之和（多头买入为负，卖出平仓为正）
```

- 买入开仓：现金减少 `权利金 × 乘数 × 手数 + 手续费`；`LO` 增加。
- 卖出平仓：现金增加 `成交价 × 乘数 × 手数 − 手续费`；`LP += 收入 − 剩余成本`；`LO` 减少。
- 到期作废：`LP −= 剩余成本`；`LO` 减少。
- 行权：见下。

### 4.4 行权

**多头 Call 行权（买入股票）**

```
新增股数 = 乘数 × 手数
股票成本 C += 行权价 × 新增股数 + 手续费 + 该合约剩余权利金成本
LO        −= 该合约剩余成本
LP         不变（成本进入股票批次）
```

**多头 Put 行权（卖出股票）**

```
卖出所得 = 行权价 × 卖出股数 − 手续费 − 该合约剩余权利金成本
share_pnl += 卖出所得 − 分摊股票成本
LO        −= 该合约剩余成本
LP         不变
```

这样处理与「期权权利金计入股票成本基础」的直觉一致，也避免同一笔权利金被重复计入 B 与 share_pnl。

### 4.5 示例

**保护性 Put**：100 股 @ $200，现价 $150；买入 1 手 140P @ $4.00。

- 成交后：`C=20,000`，`LO=400`，`S=100`；B = $200.00，C′ = $204.00。
- 到期作废：`LP=−400`，B = $204.00。
- 股价跌到 $120，Put 值 $22 卖出平仓：`LP=+1,800`，B = $182.00；股票亏 $8,000，Put 赚 $1,800，净亏 $6,200，与 B 口径一致。

**领口 Collar**：100 股 @ $200，现价 $150；买 140P @ $4，卖 160C @ $3。

- 成交后：B = $200.00，C′ = $201.00。
- 到期股价 ≤ $140：Put 行权卖出 100 股 @ $140，Call 作废；已实现 = `(14,000 − 400) + 300 − 20,000 = −6,100`。
- 到期股价 ≥ $160：Call 被指派卖出 100 股 @ $160，Put 作废；已实现 = `16,000 + 300 − 400 − 20,000 = −4,100`。
- 两端都亏损，但把亏损锁定在 $4,100–$6,100 区间——这正是 Collar 的作用，界面必须如实展示，不能只说「降本」。

**股票修复 1×2**：100 股 @ $50，现价 $40；买 1 手 40C @ $3，卖 2 手 45C @ $1。

- 净支出 $100；到期 $45：多 Call 行权买入 100 股 @ $40（权利金计入成本），2 手空 Call 作废；200 股均价 $46.50，市值 $9,000，总盈亏约 −$100。
- 到期 $50：多 Call 行权买入 100 股，2 手空 Call 被指派卖出 200 股 @ $45；总盈亏约 −$100。
- 到期 $30：三条腿全部作废，股票浮亏 $2,000 + 净支出 $100 = −$2,100。

## 5. 引擎规则

| 动作 | 校验 | 会计 |
|---|---|---|
| `OpenLong` | 合约有效；qty>0；价格>0 | 现金减少；`LO +=`；新增多头 entry / position |
| `CloseLong` | 该合约有多头 open_qty ≥ qty | 现金增加；`LP += 收入 − 成本`；entry 拆行或关闭 |
| `ExpireLong` | 多头 open_qty ≥ qty | `LP −= 成本`；entry 标记 Expired |
| `Exercise` | 多头 open_qty ≥ qty；Call 行权不需要先有股票；Put 行权需要股票 ≥ 卖出股数 | 按 §4.4 |
| `Assign` | 只允许空头；Call 需要股票足够 | 现有逻辑不变 |
| 拆股 | 同时调整多空合约的行权价与乘数 | 权利金成本总额不变 |
| 战役收尾 | `shares == 0 && 无未平仓多空期权 && (ever_held_shares || ever_held_long)` | `realized_pnl` 含 `LP` |

- `campaign_for_contract` 需要按 `(contract, side)` 匹配，允许同一合约同时存在多头与空头。
- `cycles` 仍只统计空头开仓（车轮周期），多头不计入。
- 不变量扩展：`LO == Σ 未平仓多头 entry 剩余成本`；`LP == Σ 多头已实现`；`PR/PO` 只含空头；`cash_flow` 与事件现金流一致。

## 6. 视图与界面

### 6.1 录入

- 「记一笔」增加方向选择：卖出 / 买入。
- 买入方向的动作：买入开仓、卖出平仓、到期作废、行权。
- 价格标签改为「权利金 / 股（支出）」；手续费照常。
- 行权录入只填合约、手数、日期；可预填到期日。

### 6.2 台账

- 新增「方向」列；`netPremium` 正数为收入、负数为支出（或分两列）。
- 状态新增「已行权」。
- 多头 entry 不显示年化收益率（没有保证金/权利金收入口径）。

### 6.3 持仓与到期

- 未平仓期权分「卖出 / 买入」两组。
- 买入腿显示成本、当前链估值（有链时）、剩余天数。
- 到期中心同时列多头与空头；多头动作是「行权 / 作废」。
- Call 指派预览只针对空头 Call。

### 6.4 仪表盘与报表

- 「已落袋净权利金」拆成三行：卖出期权净权利金、买入期权已实现盈亏、合计。
- 月报 / 年报增加「买入期权盈亏」列，避免把买 Put 的保险费误读成收租。
- 成本图 B / C′ 随多头盈亏重算；图例说明多头的计入方式。

### 6.5 CSV 导入

- 识别 `Buy to Open / BTO / 买入开仓 / 买开`、`Sell to Close / STC / 卖出平仓 / 卖平`、`Exercise / 行权`。
- 现有把 `exercise / 行权` 映射为 `option_assign` 的逻辑保留为兼容，但增加显式 `option_exercise`；有方向列时按方向判定。
- 行权行允许不带价格；买入开仓必须有价格。

## 7. 兼容与迁移

- **无 schema 变更**：事件表已有 `expiry / strike / right / multiplier / qty / price / fees`，`kind` 是文本。
- 旧事件重放结果不变：`LP / LO` 默认 0，B / C′ 公式退化为现有形式。
- 旧备份、JSON 导出、WebDAV 快照无需转换。
- 新字段进入 JSON 导出；旧版本应用打开新账本时，未知 kind 会报错——按现有 schema 版本策略，应提升 `SCHEMA_VERSION` 并在新版本中拒绝旧版打开，或至少在导出说明中标注最低版本。
- Android 端复用 `wheel-core` / `wheel-store`，核心逻辑自动生效；移动 UI 在 P13.5 补方向。

## 10. 风险与限制

| 风险 | 影响 | 应对 |
|---|---|---|
| 成本口径混淆 | 用户把保险费当亏损 | B / C′ 拆行展示；报表单列买入期权盈亏 |
| 多头估值依赖链 | 无链时无法显示当前价值 | C′ 用「到期作废」最坏口径；市值仅参考 |
| 行权/指派方向混淆 | 记错方向 | 事件名与 UI 明确「行权（多头）/ 被指派（空头）」 |
| 比例价差的裸露腿 | 指派时股票不足 | 引擎拒绝；扫描器默认限制手数并警告 |
| 拆股后合约调整 | 多空合约不同步 | 同一拆股事件统一调整 |
| 报表口径变化 | 历史对比失真 | 保留 `PR/PO` 只含空头；新增 `LP` 单列 |

## 11. 与 P12 的关系

- P12 首版只生成 `Side::Short` 的腿，扫描器立即可用。
- P13 完成后，P12 的腿模型不需要改口径，只需新增模板：领口、保护性 Put、海鸥、风险逆转、股票修复、比率/反向比率、日历/对角、合成多/空。
- 在 P13 完成前，扫描器对需要多头腿的策略只做**灰显 + 「需多头期权记账」**提示，不提供「记一笔」，避免方案与账本分叉。
- 日历 / 对角 / LEAPS 需要把链窗口从默认 90 天放宽到约 730 天；数据量增加但仍是一次单标的请求。
- 股票修复 1×2 的投影顺序必须是：先模拟多头 Call 行权补足股票，再模拟空头 Call 指派；否则引擎会因股票不足拒绝。扫描器与测试都要固定这个顺序。
- PMCC、合成多空、铁鹰的定位写进 UI：替代持股或区间收租，默认不混入「降本」排序，避免把叠加正股的双倍敞口包装成降本方案。

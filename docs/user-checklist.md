# Wheel Tracker 用户使用清单（0.5.5）

适用：Windows 11 x64 桌面版。
用法：第一次使用按第 0–2 节走一遍；日常只看第 3 节；导入看第 4 节；复盘看第 5 节；升级或恢复前看第 7–8 节。

> 这是一份操作清单，不是功能宣传。带 `[ ]` 的条目可以逐项勾选。

## 0. 安装与第一次启动

- [ ] 确认系统是 Windows 11 x64，已安装 WebView2 Runtime。
- [ ] 运行 `Wheel Tracker_0.5.5_x64-setup.exe`。安装包未签名，SmartScreen 提示时选择“更多信息 → 仍要运行”。
- [ ] 安装模式为 currentUser，不需要管理员权限；开始菜单会出现 `Wheel Tracker`。
- [ ] 首次启动后进入“设置 → 备份与维护”，确认版本显示 `0.5.5`，并记下数据库路径。
- [ ] 不要在浏览器预览页录入真实数据；浏览器模式只用于看界面。

## 1. 初始配置（建议一次做完）

- [ ] **规划账户**：按券商或用途建账户（例如“主账户”“退休账户”）。账户名称不可重复，最多 50 个（含已归档）。
- [ ] 在“设置 → 账户”创建账户；创建后会自动切换。
- [ ] 决定成本口径：“设置 → 成本口径 → 分红计入有效成本”。默认关闭；开启后 B / C′ 会扣除累计分红，历史成本图重算。
- [ ] 设置到期提醒：“设置 → 到期提醒”，默认提前 7 天，范围 0–60 天。提醒只在应用内显示。
- [ ] 确认自动备份：“设置 → 备份与维护 → 自动备份”，默认开启、保留 7 份。自动备份只在应用启动和运行时检查。
- [ ] 如果要用 AI 截图导入：在“设置 → AI 识别”填写 HTTPS Base URL、模型、API Key，勾选隐私同意后再启用。建议使用单独的低额度 Key。
- [ ] 立即做第一份手动备份：“设置 → 备份与维护 → 备份 SQLite”。重要账本建议填写至少 8 位密码，生成 `.sqlite.enc`。
- [ ] 把备份文件另存到其他设备或云盘；只放在本机不算备份。

## 2. 交易录入速查

进入“记一笔”后，先确认页头显示的是正确账户。所有金额均为 USD。

| 场景 | 交易类型 | 需要填写 | 注意 |
|---|---|---|---|
| 卖出开仓（STO） | 卖出开仓 | 交易日、标的、到期日、Put/Call、行权价、每手股数、手数、每股权利金、费用总额 | 权利金填“每股”，不是整笔总权利金；费用填整笔合计 |
| 买入平仓（BTC） | 买入平仓 | 从“当前持仓”选择合约，或手填合约；手数、平仓价、费用 | 选择持仓会自动回填到期日、行权价、方向、乘数、全部未平仓手数 |
| 同日滚动 | 买入平仓 + 勾选“滚动” | 平仓信息 + 新到期日、新行权价、新权利金、新开仓费用 | 新合约固定同标的、同方向、同手数；两条一起保存，任一条失败则都不入账 |
| 到期作废 | 到期作废 | 从持仓选择合约；手数 | 先确认券商已作废；日期默认到期日；过期合约不处理会一直占用资金义务 |
| 指派 / 行权 | 指派 / 行权 | 从持仓选择合约；实际被指派手数；费用 | Put 指派会自动生成买入股票，Call 指派会自动生成卖出股票；当前界面不显示现金变化，请自己核对 |
| 买入股票 | 买入股票 | 交易日、标的、股数、每股成交价、费用 | 用于建仓或补仓 |
| 卖出股票 | 卖出股票 | 交易日、标的、股数、每股成交价、费用 | 从持仓页“卖出”可直接预填全部股数 |
| 分红 | 分红 | 交易日、标的、股数、每股分红 | 系统按“每股分红 × 股数”入账；预扣税 / 费用需另记一笔“独立费用” |
| 独立费用 | 独立费用 | 交易日、标的、美元金额 | 必须选标的，会计入该标的战役收支；不能记账户级费用 |
| 现金调整 | 现金调整 | 交易日、标的、美元金额 | 计入战役收支，不改变持股数或股票成本；不要用它记入金 / 出金 |
| 拆股 / 合股 | 拆股 / 合股 | 交易日、标的、分子、分母、零股现金补偿 | 2:1 表示 1 股变 2 股；反向拆股用 1:10；有零股必须填补偿（可填 0）；先备份再操作 |

### 2.1 每笔交易保存前

- [ ] 账户正确（页头 + 侧栏）。
- [ ] 交易日期是**实际成交的美东交易日**，不是中国本地日期；凌晨录入时尤其要手动改。
- [ ] 标的代码正确；期权合约的到期日、行权价、Put/Call 正确。
- [ ] 期权乘数正确（标准美股期权 100；被拆股调整过的合约按券商显示填写）。
- [ ] 权利金 / 成交价是“每股”，费用是“整笔合计”。
- [ ] “现金净变化”“合约名义金额”“预计静态年化”与预期一致。
- [ ] 滚动时确认新合约的四项都填了。
- [ ] 保存后看仪表盘与持仓，确认股数、合约、成本变化符合预期。
- [ ] 填错了：到“台账 → 交易记录”找到该笔，点“修改”，改完保存；系统会重新回放整本账。若后续交易依赖它，会拒绝修改并提示先撤销后续交易。
- [ ] 修改会保留原记录的 ID 与序号；不需要改类型时只改错填的字段即可。

### 2.2 拆股 / 合股专项

- [ ] 先做手动备份。
- [ ] 确认分子 / 分母方向：拆股 2:1，合股 1:10。
- [ ] 确认未平仓期权的行权价与乘数会被自动调整。
- [ ] 有零股时填写现金补偿；没有零股填 0。
- [ ] 保存后检查持仓股数、期权合约、成本线。
- [ ] 拆股后的旧合约仍可用于平仓 / 指派 / 作废；不要用旧合约重新开仓。

## 3. 每日 / 每周例行

### 每天（有交易时）

- [ ] 打开应用，确认当前账户正确。
- [ ] 录入当天成交：开仓、平仓、股票买卖、分红、费用、调整。
- [ ] 看侧栏“当前持仓”徽标，处理已过期合约。
- [ ] 看仪表盘“到期提醒”，未来提醒天数内的合约是否要平仓 / 展期。
- [ ] 核对券商 App：现金变动、股数、未平仓合约与账本一致。

### 每周

- [ ] “当前持仓”页确认没有过期未处理的合约；过期合约会继续计入未平仓权利金和资金义务。
- [ ] “到期日历”看未来 30 天。
- [ ] “行情”页更新持仓报价；持仓页的价格可能是已保存的旧报价。
- [ ] 做一份手动备份，或确认自动备份已生成。
- [ ] 抽查一个战役详情：事件时间轴、成本图、Call 指派预览是否符合预期。

### 每月

- [ ] “收租台账”按标的 / 状态 / 日期筛选，导出 CSV 或 Excel 对账。
- [ ] 「报告 → 收租月报」看月度收入；注意“区间合计”包含分红、独立费用和现金调整，不等于“已落袋净收租”。
- [ ] 检查“已经了结但未录到期 / 指派”的合约。
- [ ] 把当月券商对账单与账本核对一次；差异记“现金调整”并备注原因。

## 4. 导入历史交易

### 4.1 CSV 导入

- [ ] 先从券商导出 CSV，保留原始文件；导入前做一份手动备份。
- [ ] “导入 → CSV 文件”选择文件，或粘贴 CSV 文本。
- [ ] “确认列映射”：核对日期格式、分隔符、首行表头、每个字段对应列。
- [ ] 如果是常用券商，点“保存此映射”；下次同表头会自动套用。
- [ ] “逐行确认”：逐行核对日期、类型、标的、数量、价格、费用、合约。
- [ ] 重复行默认不勾选；只有确认是两笔独立交易时才勾“允许重复导入”。
- [ ] 拆股 / 合股不会从 CSV 自动识别，必须手工录入。
- [ ] 做多期权（Buy to Open / Sell to Close）会被拒绝；不要强行改类型绕过。
- [ ] 先导入 5 行试跑，确认账本正确后再导入全量。
- [ ] 提交后记录导入行数与来源；每次导入会生成批次 ID，可在「最近导入」整批撤销，但仍建议保留原始 CSV。
- [ ] 同日多笔（尤其是 roll）导入前会提示确认先平后开；导入后可在「最近导入」整批撤销，或在交易记录中单笔撤销。

### 4.2 AI 截图导入

- [ ] 已在“设置 → AI 识别”配置 HTTPS 服务、模型和 Key，并勾选同意。
- [ ] 截图只包含必要的成交信息，裁掉账户号、姓名等敏感内容。
- [ ] 选择 PNG / JPEG / WebP / GIF，单张不超过 5 MB；确认缩略图与目标服务后，点「确认上传并识别」才会上传。
- [ ] 识别结果进入“逐行确认”；逐行核对日期、数量、价格、合约，可直接行内修改。
- [ ] 模型可能看错、漏行或混淆相似字符；不要因为“AI 识别”就跳过核对。
- [ ] 不确定的行直接取消勾选，不要提交。
- [ ] Key 以明文保存在本机 SQLite，并会进入 SQLite 备份；不要分享备份文件。

### 4.3 导入后

- [ ] 看仪表盘与持仓，确认新增事件没有破坏已有战役。
- [ ] 看“台账 → 交易记录”，确认导入事件的备注带 `导入:<来源>`。
- [ ] 如果导入了错误批次，到导入页「最近导入」整批撤销；若提示依赖冲突，先撤销依赖它的后续交易。

## 5. 复盘与导出

- [ ] “收租台账”：按标的、状态、方向、开仓日期筛选；底部有已落袋 / 未平仓汇总；可导出当前筛选结果。
- [ ] 侧栏「报告」内切换「收租月报 / 年度报表 / 战役对比」。
- [ ] 「报告 → 收租月报」：选择年份或全部年份；柱形是月度合计，折线是区间累计；可导出 CSV。
- [ ] 「报告 → 年度报表」：默认最新年份；包含净收租、股票已实现盈亏、分红、费用、现金调整；可导出 CSV 和两张工作表的 Excel。
- [ ] 年度报表是已实现口径，不含未平仓权利金和股票浮盈亏，也不是税务申报表。
- [ ] “战役对比”位于「报告 → 战役对比」：横轴持续天数，纵轴已实现收益 ÷ 峰值投入；进行中战役的已实现收益不含未平仓权利金与浮盈亏。
- [ ] “战役详情”：看成本阶梯、Call 指派预览、事件时间轴、股票批次。
- [ ] 导出前确认当前账户；所有报表和台账都是单账户口径。
- [ ] 导出的 CSV / Excel / JSON 放到账本备份之外的目录，避免和数据库混在一起。

## 6. 多账户管理

- [ ] 侧栏底部切换账户；页头会显示当前账户名。
- [ ] “设置 → 账户”可新建、重命名、切换、归档、恢复、删除。
- [ ] 新建账户后会自动切换；账户名称不可重复。
- [ ] 归档：从切换器隐藏，数据保留；至少保留一个可用账户。
- [ ] 恢复：重新出现在切换器中。
- [ ] 删除：只允许删除从未有过任何事件（含已撤销）的账户；有交易的账户只能归档。
- [ ] 最后一个可用账户不能归档或删除。
- [ ] 归档 / 删除当前账户时，应用会自动切到另一个可用账户。
- [ ] 多账户没有合计总览；需要总敞口时，逐个账户记录后手工汇总。
- [ ] 成本口径（分红是否计入）是全局设置，会影响所有账户。
- [ ] 账户币种固定 USD；“币种”列不是多币种支持。
- [ ] 归档前如需要留档，先导出该账户的台账 / Excel。

## 7. 备份与恢复

### 7.1 日常备份

- [ ] “设置 → 备份与维护 → 备份 SQLite”生成手动备份。
- [ ] 敏感账本填写 8–128 位密码，生成 `.sqlite.enc`；密码单独保存，遗失无法恢复。
- [ ] 自动备份默认开启、保留 7 份；只清理 `auto-*.sqlite`，手动备份和安全快照不会自动删除。
- [ ] 备份文件在数据库旁的 `backups/` 目录；重要备份复制到其他设备。
- [ ] 备份列表显示类型、大小、UTC 时间、是否加密。
- [ ] 当前版本没有删除备份的界面入口；清理磁盘时不要误删 `pre-restore-*` 安全快照。

### 7.2 恢复

- [ ] 先做一份当前账本的手动备份。
- [ ] “设置 → 备份与维护 → 备份列表”选择备份，点“校验与恢复”。
- [ ] 加密备份先输入密码，点“解密并校验”。
- [ ] 确认校验通过：完整性、事件数、账户数、报价数；有问题不要恢复。
- [ ] 点“恢复此备份…”，确认后暂存恢复。
- [ ] **完全退出应用**（不是只关窗口），重新启动。
- [ ] 重启后看恢复状态横幅；成功会显示上次恢复结果，失败会保留原库并说明原因。
- [ ] 恢复前会自动生成 `pre-restore-*.sqlite` 安全快照；恢复失败时用它回退。
- [ ] 恢复期间账本只读；在重启前不要继续录入。
- [ ] 从其他机器带来的备份，需要先复制到本机 `backups/` 目录，界面才能看到；当前没有“打开文件夹”按钮，按设置页显示的数据库路径找到它。
- [ ] 建议每季度做一次恢复演练，确认备份真的可用。

## 8. 升级

- [ ] 升级前做一份手动备份，并记录当前版本。
- [ ] 阅读 `CHANGELOG.md` 与发布说明。
- [ ] 完全退出应用。
- [ ] 运行新安装包覆盖安装；当前为 currentUser 安装。
- [ ] 启动后确认“设置 → 备份与维护”版本号正确。
- [ ] 检查账本、持仓、报表、备份列表。
- [ ] 0.5.5 的数据库 schema 为 3；0.3.0 不能打开 schema 3 的数据库。回滚前先恢复旧版备份。
- [ ] 安装包未做代码签名，可能出现 SmartScreen；应用启动时会检查 GitHub Release，有新版时页面顶部会显示更新横幅。
- [ ] 更新流程：点击「下载并安装」→ 等待安装器完成 → 点击「重启应用」。更新包会先验签，签名不符不会安装。
- [ ] 覆盖安装保留账本、备份与设置；卸载也会保留 `%APPDATA%\com.wheeltracker.desktop\` 下的数据。

## 9. 数据安全

- [ ] 实时数据库是明文 SQLite；建议开启 Windows 磁盘加密（BitLocker）并保护 Windows 账户。
- [ ] 手动备份可加密；自动备份和安全快照始终是普通 SQLite。
- [ ] AI API Key 以明文保存在本机 SQLite，会随备份复制；JSON 导出不包含 Key。
- [ ] 不要把包含 API Key 的 SQLite 备份发给别人。
- [ ] 不要用文本编辑器或 SQLite 工具直接改数据库；需要修正时用应用内撤销 / 重录。
- [ ] 不要同时打开两个应用实例；当前没有单实例保护，可能造成写入竞争或误操作。
- [ ] 浏览器预览页不连接真实账本，不要在里面录入真实交易。
- [ ] 到期提醒只在应用内显示；需要提醒时保持应用运行，或自己另设日历提醒。

## 10. 已知限制

- [ ] 只支持卖出期权车轮策略；不支持买入开仓、保护性 Put、价差、组合策略。
- [ ] 统一 USD；不支持多币种。
- [ ] 没有账户级入金 / 出金模型；`现金调整` 会计入战役收益，不能当转账用。
- [ ] 没有账户现金余额；只有 Put 资金义务和已实现 / 未平仓权利金。
- [ ] 多账户没有合计总览，只能逐账户查看。
- [ ] 交易只能撤销、不能直接编辑；撤销后需重录。导入确认页内可修改待入账行。
- [ ] 没有审计日志查看器；软删除记录保留在数据库和备份中，但界面不展示。
- [ ] 导入可整批撤销；单笔撤销仍在交易记录中操作。
- [ ] 没有系统通知 / 托盘提醒。
- [ ] 行情来自公开接口，可能延迟或不可用；报价只用于对照，不改变成本。
- [ ] 已支持应用内自动更新；没有 Authenticode 代码签名、崩溃上报。
- [ ] 年度报表不是税务申报表；不含税务计算。
- [ ] 同一标的在同一账户内只有一个进行中战役；并行轮子会合并。
- [ ] 拆股不保留小数股；零股用现金补偿。
- [ ] 恢复只能选 `backups/` 目录内的文件；外部备份要先复制进来。
- [ ] 恢复不会自动重启；「确认安排恢复」只暂存恢复请求，需要手动完全退出再启动。

## 11. 常见问题

| 现象 | 处理 |
|---|---|
| 保存失败：标的代码不能为空 | 标的为空；用下拉搜索选择代码后重试 |
| 保存失败：价格与费用必须为有限的非负数 | 价格或费用为空 / 负数；检查输入 |
| 保存失败：期权合约必须同时填写到期日、行权价和方向 | 期权缺到期日、行权价或 Put/Call |
| 撤销被拒绝 / 撤销后的事件历史无效 | 后面有交易依赖它；先撤销后续交易，或改用现金调整修正 |
| 恢复后数据没变 | 暂存后必须完全退出并重新启动，不是只关窗口 |
| 导入提示重复，但确实是两笔 | 核对日期、标的、数量与金额；确认后勾“允许重复导入” |
| 账户删除按钮灰掉 | 账户有交易（含已撤销）或它是最后一个可用账户；只能归档 |
| 持仓价格不动 | 行情接口失败或标的没有自动刷新；到“行情”页手动更新或手动校准 |
| 到期合约还在列表 | 到期不会自动入账；确认券商作废后录入“到期作废” |
| 年度报表没有今年 | 今年还没有已实现事件；空状态会说明，先看「报告 → 收租月报」或战役详情 |
| 版本显示 — | 应用信息读取失败时的兜底；重启应用，仍异常则记录错误 |

## 12. 一页纸日常流程

1. 打开应用 → 确认账户 → 记一笔（交易日按美东）。
2. 看持仓 / 到期提醒 → 处理到期、指派、平仓、roll。
3. 看仪表盘 → 核对现金、股数、合约。
4. 每周更新行情、做备份、核对券商。
5. 每月看台账 / 月报 / 年报，导出留档。
6. 升级或恢复前：先备份，再操作；恢复后完全重启。

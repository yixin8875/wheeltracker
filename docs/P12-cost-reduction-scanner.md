# P12 — 降本扫描器（Cost-Reduction Scanner）

> 状态：设计稿 · 策略范围已确认（全量四组）· 待开发确认 · 2026-11-20
> 适用端：Windows 桌面端（首版）；Android 客户端后续复用同一引擎
> 关联：[成本模型](../DESIGN.md) · [全部持仓](P9-holdings.md) · [CSV 导入](P3-acceptance.md)

## 0. 一句话

针对**被套的正股持仓**，用真实或延迟的期权链做穷举式情景扫描，列出备兑 Call、卖出 Put 摊平、备兑宽跨等方案的**到期后成本、即时成本、保本价、被行权结果、资金占用与风险**，用户确认后一键预填「记一笔」。

扫描器只做**只读情景分析**，不写账本、不连接券商、不自动下单。

---

## 1. 先把口径说清楚

这个功能最大的风险不是算不出来，而是把「降本」说成了「解套」。方案里必须同时回答四个问题：

### 1.1 三个数字，缺一不可

沿用现有 A / B / C′ 三轨：

| 口径 | 含义 | 卖出期权后 |
|---|---|---|
| A | 纯股票成本 | **永远不变** |
| B | 扣除**已落袋**净权利金与计入口径的分红 | 权利金到期作废后才下降 |
| C′ | 再扣除**未平仓**净权利金（理论成本） | 成交当下就下降 |

所以扫描结果对每个方案同时给出：

- **到期后成本 B′**：假设新卖出的期权到期作废，B 轨会变成多少。这是真正的「降本」。
- **即时成本 C′**：成交后立刻显示的理论成本（含尚未落袋的新权利金）。这是账本当下的样子。
- **保本价 B′**：股价需要涨到哪里才回本。

### 1.2 降本 ≠ 盈利，也可能锁亏

备兑 Call 的权利金会在 B 轨上「抹掉」一部分成本，但如果行权价低于成本价，股票被叫走时会把浮亏变成**已实现亏损**。扫描器必须把「被行权后的总盈亏」和「锁定亏损金额」放在同一行，不能只展示漂亮的降本数字。

### 1.3 卖出 Put 不是降本，是加仓

卖出 Put 摊平会：

- 用现金换取权利金；到期作废才降低现有股票成本；
- 一旦被指派，持股数增加、总成本增加，**下跌风险同步放大**；
- 若现金未记录，无法校验资金，默认禁用该策略。

### 1.4 扫描是情景分析，不是投资建议

所有排序和标签都是机械计算。界面固定展示：

> 本页基于延迟行情与情景假设，仅用于记账前的方案比较，不构成投资建议；期权价格可能已变化，成交前请以券商报价为准。

## 2. 现有基础与约束

| 能力 | 现有实现 | 本功能如何复用 |
|---|---|---|
| 事件溯源 / 重放 | `wheel-core::engine::replay` | 候选方案用**假设事件**投影，不落库 |
| 指派模拟 | `wheel-app` 的 `call_scenarios`（`commands.rs:805`） | 同一套「追加事件再重放」模式 |
| 成本三轨 | `Campaign::cost_a / cost_b / cost_c` | 直接复用，不另写公式 |
| 期权合约与乘数 | `OptionContract { expiry, strike, right, multiplier }` | 方案腿的落库格式 |
| 账户现金 | `DerivedState::account_cash`、Put 义务 | 判断卖 Put 的资金上限 |
| CSV 映射向导 | `ImportWizard` + `import_preview/commit` | 期权链粘贴导入复用交互模式 |
| 行情 | `wheel-store/src/market.rs`，腾讯财经，**仅股票** | 提供现价；期权链需新增数据源 |
| 多账户 | 账户隔离 | 扫描按当前账户；不跨账户合并持仓 |
| 移动端 | 复用 `wheel-core` + `wheel-store` | 引擎可复用，UI 后续再做 |

### 2.1 关键约束：账本目前没有「买入期权」

`OptionAction` 只有 `OpenShort / Close / Expire / Assign`（`model.rs:93`），即**只记录卖出期权**。因此策略分两层（完整目录见 §9.3）：

- **现有账本即可记录**：备兑 Call（含阶梯）、卖出 Put（含阶梯）、备兑宽跨、滚动、深度实值备兑、加仓 + 备兑。
- **需要买入期权**：领口、保护性 Put、海鸥、风险逆转、股票修复、比率/日历/对角价差、合成多/空。这些要等 [P13 多头期权记账](P13-long-options.md) 完成；在此之前只灰显，不提供「记一笔」。
- 所有涉及买入腿的方案，不能伪装成卖出腿记账。

## 3. 数据层：期权链快照

### 3.1 三个来源，按优先级

| 来源 | 说明 | 可靠性 | 默认 |
|---|---|---|---|
| A. 自动获取（Nasdaq） | `api.nasdaq.com/api/quote/{SYMBOL}/option-chain` 延迟报价，无需 API Key；含 bid/ask/last/成交量/未平仓量，**不含 IV 与 Greeks** | 中高（本机实测可用，见 §3.4） | 可选开关，默认开启 |
| B. 手动粘贴 / CSV | 从券商（富途、老虎、IBKR、嘉信等）复制期权链，或下载 CSV；沿用「表头映射 → 预览 → 确认」向导 | 高 | 始终可用 |
| C. 单条手工录入 | 指定到期日、行权价、C/P、买价/卖价（或权利金） | 高 | 兜底 |

> **实测结论（2026-11-20，本机网络）**：CBOE `cdn.cboe.com` 与 `cdn-api.cboe.com` 被 Cloudflare 拦截（HTTP 403），Yahoo 期权接口同样 403；Nasdaq 接口可用。因此默认自动源为 **Nasdaq**，CBOE 仅作为可选适配器保留，不默认启用。

**理论估算兜底**：Nasdaq 不返回 IV 与 Greeks，因此用 Black–Scholes 从中间价**反解 IV**，再计算 Delta/Gamma 等；反解失败（无有效买卖价）则留空，排序退化为 OTM% 与价差。估算值一律标注「估算」，只用于排序参考，**不用于预填成交价**。

### 3.2 数据表（schema 4 → 5）

```sql
-- 每个标的一条最新快照元数据
CREATE TABLE option_chain_snapshot (
  symbol          TEXT PRIMARY KEY,
  source          TEXT NOT NULL,          -- 'nasdaq' | 'cboe' | 'manual' | 'mixed'
  as_of           TEXT NOT NULL,          -- 行情源的美东报价时间
  fetched_at      TEXT NOT NULL,          -- 本机拉取时间
  underlying      REAL,                   -- 快照时的标的参考价
  notes           TEXT NOT NULL DEFAULT ''
);

-- 每张合约一行；刷新时按 symbol 整体替换
CREATE TABLE option_quotes (
  symbol          TEXT NOT NULL,
  expiry          TEXT NOT NULL,          -- YYYY-MM-DD
  strike          REAL NOT NULL,
  right           TEXT NOT NULL,          -- 'C' | 'P'
  bid             REAL,
  ask             REAL,
  last            REAL,
  mark            REAL,                   -- 中间价，缺省由 bid/ask 计算
  iv              REAL,                   -- 年化，0.35 = 35%
  delta           REAL,
  gamma           REAL,
  theta           REAL,
  vega            REAL,
  open_interest   INTEGER,
  volume          INTEGER,
  multiplier      INTEGER NOT NULL DEFAULT 100,
  updated_at      TEXT NOT NULL,
  PRIMARY KEY (symbol, expiry, strike, right)
);
```

原则：

- **期权报价绝不写入 `prices` 表**，不污染成本图、盯市图和持仓盈亏口径。
- 每个 symbol 只保留最新一份快照；刷新即替换。不保留历史链（没有回测需求）。
- 迁移在 `wheel-store::store::open` 中按现有模式执行，`SCHEMA_VERSION` 升到 5。
- 备份 / 恢复沿用现有整库快照，自动包含链数据。

### 3.3 新鲜度与失败处理

| 状态 | 判定 | 界面 |
|---|---|---|
| 新鲜 | `fetched_at` ≤ 15 分钟 | 绿色圆点 + 报价时间 |
| 延迟 | 15 分钟 – 1 个交易日 | 黄色「延迟」标签 |
| 过期 | 超过 1 个交易日 | 红色「过期」标签，扫描仍可运行但每行带警告 |
| 无数据 | 无快照 | 空状态，引导「获取」或「导入」 |

- 自动获取失败：**保留旧快照**，明确报错，提示改用粘贴导入；不静默回退到估算。
- 扫描结果每行显示权利金来源：`买价` / `中间价` / `估算`。
- 默认卖出用**买价**（保守口径），可切换为中间价。

### 3.4 解析与来源边界

- **实测（2026-11-20，本机）**：CBOE 与 Yahoo 均被 Cloudflare 拦截（HTTP 403）；Nasdaq 内部报价接口可用——AAPL 90 天窗口返回 980 行 / 384 KB / 约 4 秒。
- Nasdaq 请求示例（单标的、90 天窗口、一次一标的，禁止并发批量）：

```
https://api.nasdaq.com/api/quote/AAPL/option-chain
  ?assetclass=stocks
  &limit=10000
  &fromdate=2026-11-20&todate=2027-03-31
  &exchcode=oprac&callput=callput&money=all&type=all
```

- 响应按「行权价」一行同时包含 Call 与 Put：`c_Bid/c_Ask/c_Last/c_Volume/c_Openinterest` 与 `p_Bid/…`，入库时按 `strike` 拆成 C/P 两条。
- `expiryDate` 只有 `"Dec 18"`，没有年份：用 `expirygroup`（如 `"December 18, 2026"`）或 `drillDownURL` 中的 OCC 代码（如 `aapl--261218c00315000`）还原完整到期日；以 OCC 代码为准，同时用它校验行权价与 C/P。
- `"--"` 或空字符串视为无报价；缺失 bid/ask 的合约保留但不参与默认排序。
- Nasdaq 是网站内部接口，未公开承诺稳定；解析失败不得影响账本，必须回退到手动导入，并保留上一份快照。
- 请求只发送标的代码，不发送账户、持仓或交易历史；不把链数据上传或转发。
- 数据用于个人记账参考，界面注明来源与延迟；不做再分发。

## 4. 扫描引擎

放在新 crate `crates/wheel-scan`（依赖 `wheel-core` + `time`，`serde` 仅用于 IPC 序列化；无网络、无数据库）：

```
wheel-scan/src/
  pricing.rs      Black–Scholes 定价、Greeks、隐含波动率求解
  strategy.rs     方案模板、候选生成、指标计算
  projection.rs   构造假设事件 → wheel_core::replay → 精确结果
```

### 4.1 输入

**持仓快照**（来自 `DerivedState` + `prices`）：

- 账户、战役、标的、股数 `S`
- `cost_total`、`premium_realized`、`premium_open`、分红、现金
- 现有未平仓 Call / Put（手数、行权价、到期日、乘数）
- 最新参考价 `P`（无价格则拒绝扫描并提示先更新行情）

**扫描设置**（全局默认 + 页面即时调整，不落库也可，建议记住上次选择）：

| 设置 | 默认 | 说明 |
|---|---|---|
| 到期窗口 DTE | 14 – 45 天 | 只看该区间内的到期日 |
| 链窗口 | 90 天（可选 730 天） | 日历/对角/LEAPS 需要更远到期；数据量随之增加 |
| Delta 区间 | 0.15 – 0.35 | 无 Greeks 时退化为 OTM% 区间 |
| 行权价约束 | `K ≥ 成本 B` | 默认不显示会锁亏的 Call |
| 接受锁定亏损 | 关 | 开启后才显示 `K < 成本 B` 的方案 |
| 允许卖出 Put | 关 | 需先记录入金/出金或填写可用现金 |
| 最多追加资金 | 当前持仓市值的 100% | 卖 Put 的总行权价上限 |
| 每手手续费 | $0.65 | 计入净权利金；可为 0 |
| 权利金口径 | 买价 | 可切换中间价 |
| 流动性过滤 | OI ≥ 100 且买卖价差 ≤ 10% | 可关闭 |
| 无风险利率 r | 4% | 仅用于 BS 估算与概率 |
| 股息率 q | 0% | 可按标的覆盖 |

### 4.2 方案模板

#### A. 备兑 Call（Covered Call）

- 只用**未被现有 Call 覆盖的股票**：`free_shares = S − Σ(现有 Call 手数 × 乘数)`，向下取整到手。
- 每个到期日 × 每个行权价生成一个候选，数量取 `max_contracts = free_shares / multiplier`（v1 不做阶梯分批）。
- 核心指标：

```
Δ            = 权利金/股 × 乘数 × 手数 − 手续费
到期后成本 B′ = (cost_total − premium_realized − Δ − 计入口径分红) / S
即时成本 C′   = (cost_total − premium_realized − premium_open − Δ − 分红) / S
每股降本      = 原 B − B′
权利金回报    = Δ / (P × S)
年化（按行权价）= (Δ / (K × 乘数 × 手数)) × 365 / DTE
被行权总盈亏  = (K × 卖出股数 − 分摊成本) + 已落袋权利金（含 Δ） + 分红 + 调整
```

- 部分行权（手数 × 乘数 < S）时，额外给出**剩余持仓的 B′**：
  `(cost_total − 分摊成本 − (premium_realized + Δ) − 分红) / (S − 卖出股数)`。
  权利金会摊到全部剩余股票上，这是备兑最容易被误解的地方，必须单独展示。

#### B. 卖出 Put 摊平（Cash-Secured Put）

- 每个到期日 × 行权价生成候选，行权价需低于现价（默认 `K ≤ 0.98 × P`）。
- 手数上限：`min(现金 / (K × 乘数), 用户追加资金上限 / (K × 乘数))`；现金未记录时禁用。
- 两种结果：

```
到期作废：B′ = (cost_total − premium_realized − Δ − 分红) / S      // 现有股票降本
被指派：  shares′ = S + 手数 × 乘数
          cost_total′ = cost_total + K × 手数 × 乘数 + 指派费
          B′ = (cost_total′ − premium_realized − Δ − 分红) / shares′  // 摊薄后的平均成本
```

- 风险指标：追加资金、指派后总股数、现价 −10% / −20% 情景下的总浮亏，以及**与「不卖 Put」相比多亏多少**。
- 默认最多把持股数翻倍（可在设置中调整），避免一次摊平过度集中。

#### C. 备兑宽跨（Covered Strangle）

- 同时选中一个 A 方案和一个 B 方案，展示合并后的权利金、成本、资金占用与四种到期组合（Call 行权 / Put 行权 / 都行权 / 都不行权）。
- v1 只做「最优单腿组合」：按当前排序取第一条 Call + 第一条 Put，用户可在详情里替换其中一条。

#### D. 滚动现有 Call（Roll）

- 当已有未平仓 Call 且现价接近或高于行权价时出现。
- 组合两条腿：`买入平仓`（按卖价）+ `卖出开仓`（按买价，更远到期或更高行权价），显示净权利金、新旧成本、是否延后锁定亏损。
- 复用现有「滚动」录入（BTC + STO 一次提交）。

### 4.3 精确投影：不另造一套会计

候选的**头部指标**（被行权总盈亏、剩余持仓成本、是否关闭战役）不手算，而是：

1. 复制当前账户事件流；
2. 追加假设的 `OpenShort` 事件（卖出方案腿），需要时再追加到期日的 `Assign` 事件；
3. 调用 `wheel_core::replay`；
4. 从投影后的 `Campaign` 读取 B / C′ / 已实现盈亏 / 剩余股数。

与 `call_scenarios` 完全同一模式，保证扫描结果与真实记账后的数字**逐分一致**。假设事件**从不落库**，只存在于本次计算。

性能：单标的链过滤后通常 < 300 个候选；先用解析公式过滤和排序，再对前 40 个候选做投影，单次扫描在毫秒级完成。

### 4.4 排序预设（不做黑箱评分）

不提供「综合分」，避免用伪科学掩盖取舍。四个预设只改变过滤与排序：

| 预设 | 过滤 | 排序 |
|---|---|---|
| 稳健收租 | Δ ≤ 0.20，K ≥ 成本 B，OI/价差达标 | 年化 → 行权价距离 |
| 平衡降本 | Δ 0.20 – 0.30，K ≥ 成本 B | 每股降本 → 年化 |
| 激进解套 | Δ 0.30 – 0.45，允许 K < 成本 B | 到期后 B′ 最低 |
| 加仓摊平 | 仅卖出 Put，Δ 0.15 – 0.30 | 指派后 B′ 最低 |

所有列可点击排序；每行展示来源与风险标签。

### 4.5 风险标签

| 标签 | 触发条件 |
|---|---|
| 锁定亏损 | Call 行权价 < 成本 B，被行权后总盈亏为负 |
| 加仓放大 | Put 指派后持股数 > 原持股数 |
| 资金不足 | 卖 Put 的行权价总额 > 可用现金 |
| 覆盖不足 | 股数不是乘数整数倍，或部分股票未被 Call 覆盖 |
| 深度实值 | Call Δ > 0.60，提前指派风险较高 |
| 临近到期 | DTE ≤ 3 且行权价距现价 ≤ 2%（Pin risk） |
| 流动性差 | OI < 100 或买卖价差 > 10% |
| 链已过期 | 快照超过 1 个交易日 |
| 估算价格 | 权利金来自 Black–Scholes 估算 |
| 分红临近 | 快照日期距到期日跨过除息日（v2 接入分红日历后） |

### 5.3 交互流程

1. 进入页面 → 自动列出**所有亏损持股**（现价 < 成本 B）；也可手动选择任意持股。
2. 无链数据时先显示「获取 Nasdaq 延迟链」与「粘贴导入」两个入口。
3. 点击「扫描」→ 本地计算，1 秒内返回。
4. 调整预设 / 筛选 → 即时重排（不重新投影全部候选，只重排缓存结果）。
5. 展开「详情」→ 方案腿、到期情景表、风险说明。
6. 点击「记一笔」→ 跳转录入页并预填：
   - 类型 `option_open`
   - 标的、到期日、行权价、C/P、乘数
   - 手数、权利金（默认买价，可改）
   - 手续费（默认设置值）
   - 备注自动写 `降本扫描 · 备兑Call · 到期后成本 196.80`，可编辑
   - **不自动提交**，仍走现有校验与手动保存。

### 5.4 方案详情：情景表

以到期价格 `x` 为横轴，展示经济盈亏（含股票市值，不是已实现）：

**备兑 Call（K 为行权价）：**

| 到期价 | 持股 | 股票市值 | 权利金 | 总盈亏 |
|---|---|---|---|---|
| x < K | S | x × S | Δ | x×S + Δ − cost_total + 分红 |
| x ≥ K | 0 | — | Δ | K×S + Δ − cost_total + 分红 |

**卖出 Put：**

| 到期价 | 持股 | 总盈亏 |
|---|---|---|
| x < K | S + nM | x×(S+nM) + Δ − cost_total − K×nM + 分红 |
| x ≥ K | S | x×S + Δ − cost_total + 分红 |

默认取 5 个情景点：`现价 −20%`、`现价 −10%`、`现价`、`行权价`、`成本 B`；可拖动查看。

详情中同时显示「与不操作相比」的差额，避免只看到绝对收益。

### 5.5 空状态与错误

| 场景 | 展示 |
|---|---|
| 没有亏损持股 | 「当前没有低于成本价的持股」，列出全部持股入口 |
| 没有现价 | 「先更新标的行情」，提供刷新按钮 |
| 没有链 | 「获取延迟期权链」或「从券商粘贴期权链」 |
| 链过期 | 顶部黄色警告 + 每行「过期」标签 |
| 自动获取失败 | 保留旧链，提示网络原因与手动导入 |
| 现金未记录 | 卖 Put 开关禁用，提示「先在账户现金录入入金/出金」 |

### 5.6 视觉

沿用当前「纸面账本」风格：无渐变、无发光；表格使用等宽数字；风险标签用克制的红/黄；估算值用斜体或虚线下划线；金额统一 USD。

## 8. 测试与验收

### 8.1 单元与属性测试

- BS 定价与 Greeks：对照已知解析值；看涨看跌平价；IV 求解往返误差 < 1e-4。
- 候选生成：现有 Call 覆盖后的可用股数；非 100 整数倍；零手数；无现价；无链。
- 指标公式：与 `wheel_core::replay` 投影逐项比对（B′、C′、被行权盈亏、剩余成本）。
- 投影不落库：扫描前后事件数、`seq`、账本哈希不变。
- 排序预设：过滤边界（Δ、K 与成本、DTE、OI、价差）。
- 链解析：Nasdaq 字段缺失、`"--"` 空报价、`expiryDate` 缺年份、重复行、坏行跳过。
- 迁移：schema 4 → 5 后旧库可读写、备份可恢复。

## 9. 风险、边界与后续

### 9.1 主要风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 用户把「降本」当「回本」 | 错误决策 | 同时展示 B′、C′、保本价、被行权总盈亏；固定免责声明 |
| 期权链不可达 / 过期 | 扫描无效 | Nasdaq 为未公开承诺的内部接口，可能随时变更；手动导入兜底；过期标签；不静默估算 |
| 理论价格偏差 | 排序误导 | 估算值显著标记，不用于预填成交价 |
| 卖 Put 放大亏损 | 资金损失 | 默认关闭；现金与追加资金上限；下跌情景对比 |
| 早期指派 / Pin risk | 结果与预期不符 | 深度实值、临近到期标签；文档说明 |
| 快照与拆股不一致 | 合约不可用 | 链快照按交易日校验；拆股后提示刷新 |
| 扫描结果被当成承诺 | 合规与信任 | 只做机械情景分析，不提供买卖建议 |

### 9.2 已知限制

- 价格延迟约 15 分钟，不能替代券商实时盘口。
- 不判断用户的风险承受能力、税务与组合层面的相关性。
- 不覆盖跨账户对冲（A 账户持股、B 账户卖 Call 不会被识别）。
- 不做美式期权提前行权的精确概率，只用 Delta 近似。
- 分红除息日、借券费率等外部数据 v1 不接入。

### 9.3 策略目录：还能支持多少

可以支持的策略远不止首版四种。按「账本是否需要买入期权」分三层。

#### 第一层：现有账本即可记录（P12 / P12.5，不需要改引擎）

| 策略 | 腿 | 降本逻辑 | 主要风险 |
|---|---|---|---|
| 备兑 Call | 卖 Call | 权利金降低 B | 上行封顶；K < 成本时锁亏 |
| 备兑 Call 阶梯 | 2–3 个行权价/到期分批卖 | 分批覆盖，平滑行权 | 管理复杂；部分覆盖 |
| 备兑宽跨 | 卖 Call + 卖 Put | 两份权利金 | 下跌敞口放大 |
| 卖出 Put 摊平 | 卖 Put | 权利金降本；指派后摊薄均价 | 加仓放大亏损 |
| 卖出 Put 阶梯 | 多行权价/到期分批 | 分批建仓 | 资金占用与集中度 |
| 滚动 Call | BTC + STO | 延期/提高行权价换净权利金 | 可能净支出；继续让渡上行 |
| 深度实值备兑 | 卖 ITM Call | 高权利金，接近锁定退出价 | 大概率被行权，锁定亏损 |
| 加仓 + 备兑 | 买股票 + 卖 Call | 摊低均价并收租 | 追加资金；下跌双倍 |
| 比例备兑（卖超） | 卖 Call 超过持股覆盖 | 权利金更高 | 裸露 Call；**默认禁止** |

这些全部可以用现有事件表达（多条 STO / BTC / SharesBuy），扫描器只需增加模板与分配规则。

#### 第二层：需要「买入期权」记账（P13）

| 策略 | 腿 | 作用 | 账本缺口 |
|---|---|---|---|
| 保护性 Put | 股票 + 买 Put | 设定下跌下限；保险费抬高成本 | 买 Put |
| 领口 Collar | 股票 + 买 Put + 卖 Call | 用 Call 权利金支付 Put，封顶封底 | 买 Put |
| 海鸥 Seagull | 领口 + 卖 Put | 用卖 Put 补贴领口，增加下行 | 买 Put |
| 风险逆转 | 卖 Put + 买 Call | 看涨修复；净收或净付 | 买 Call |
| 股票修复 | 买 1 ATM Call + 卖 2 OTM Call | 反弹到上沿可修复亏损 | 买 Call |
| 比率价差 | 买 1 + 卖 2/3 | 修复/收租的通用形式 | 买 Call |
| 反向比率 | 买 2 + 卖 1 | 大涨受益，小涨亏权利金 | 买 Call |
| 看涨价差 | 买低行权 + 卖高行权 | 低成本追涨/修复 | 买 Call |
| 日历价差 | 买远月 + 卖近月 | 收租/波动率 overlay，非直接降本 | 买远月；链窗口需更长 |
| 对角价差 / PMCC | 买 LEAPS + 卖近月 | 替代持股（不与正股叠加） | 买 LEAPS；链窗口需更长 |
| 合成多头 | 买 Call + 卖 Put | 替代持股（不与正股叠加） | 买 Call |
| 合成空头 | 买 Put + 卖 Call | 锁定退出价（与正股组合即领口） | 买 Put |
| 铁鹰 / 铁蝶 | 多腿 | 区间收租，默认不进入「降本」排序 | 多头腿 |

#### 第三层：研究型，暂不做

多轮滚动优化、Delta 中性覆盖、财报/事件波动率 overlay、跨标的组合对冲、税损收割——需要历史期权链、波动率曲面或税务数据，等前两层稳定后再评估。

### 9.4 统一表示：策略只是腿的组合

扫描器内部统一为：

```rust
struct StrategyLeg { side: Side, right: Right, expiry: Date, strike: f64, qty: u32, price: f64 }
struct StrategyCandidate { kind: StrategyKind, legs: Vec<StrategyLeg>, /* 指标 */ }
```

候选生成只负责「产腿」，成本、被行权结果、剩余持仓仍由 `wheel-core` 投影计算。P12 只产生 `Side::Short` 的腿；P13 打开 `Side::Long` 后，新增策略只需要新增模板，不需要重写会计口径。

### 9.5 P13 多头期权账本扩展（摘要）

这是支持第二层策略的前置条件，单独设计见 [P13 多头期权记账](P13-long-options.md)。核心改动：

- 新增 `OpenLong / CloseLong / ExpireLong / Exercise` 四种期权动作；
- `PremiumEntry` / `OptionPosition` 增加 `side`；
- Campaign 新增「买入期权已实现盈亏」与「未平仓买入成本」，B / C′ 按「未平仓买入腿到期作废」的最坏口径扩展；
- 事件表无需迁移（`kind` 是文本），旧账本重放结果不变；
- 录入、台账、持仓、到期中心、报表、CSV 导入都要增加方向；
- 多头行权：买 Call 行权把权利金计入股票成本；买 Put 行权把权利金冲减卖出所得。

不要在扫描器里用「假多头腿」绕过账本：一旦用户按方案下单，账本必须能如实记录，否则扫描结果与账本会分叉。

- **M3 桌面 UI**：侧栏「日常 → 降本扫描」；持仓选择、链状态与抓取 / 粘贴导入、预设与筛选、结果表、展开详情（指派结果与 −10% / −20% 情景）、「记一笔」预填；战役详情新增「查看降本方案」。
- **与设计的差异**：
  - Nasdaq 不提供 IV / Greeks，扫描器用权利金反解 IV；反解失败时只用 OTM 距离参与 Delta 过滤，且不展示 ITM 概率。
  - 预设的 Δ 区间由页面写入设置（`Preset::delta_bounds()` 供界面取默认值），引擎只认 `ScanSettings`，避免双份真相。
  - 卖 Put 的下跌情景在投影后按当前价 −10% / −20% 计算，并给出「不操作」对照。

# Wheel Tracker 产品设计审视（0.4.1）

日期：2026-11-04
范围：0.4.1 Windows 桌面版。基于当前源码、界面文案与既有验收记录做静态审阅，未做用户访谈或可用性测试。

## 1. 总体判断

这个版本已经过了“功能有没有”的阶段：事件重放、三轨成本、战役生命周期、拆股 / 乘数、导入、报表、多账户、备份恢复都有完整闭环，而且账本正确性优先的设计很扎实。

真正别扭的地方，不是缺功能，而是**软件按“账本如何存储”组织，用户却按“我现在要做什么”使用**。于是出现几类摩擦：

- 安全但绕路：撤销藏在设置里，改一笔交易要先撤销再重录。
- 完整但难读：四个页面都在说“收益”，口径却不同。
- 严谨但空白：指派是车轮策略最关键的节点，录入时却不显示现金变化和指派后的持仓。
- 隔离但看不见全局：多账户数据完全分开，却没有一个只读的总览。

**最优先的五个问题**

1. 录入日期用本地日期，账本 / 报表用 UTC，行情用美东——同一笔交易有三个“今天”。
2. 交易只能撤销、不能更正；撤销入口在“设置 → 交易记录”，且没有审计日志查看器。
3. 导入确认页只能改交易类型；整批导入不能撤销；费用 / 调整的去重指纹漏了金额。
4. 指派录入没有现金与持仓预览；只有 Call 指派预览，没有 Put 指派预览。
5. 收租月报、年度报表、仪表盘、战役对比的“收益”定义不同，但界面用词相同。

## 2. 具体问题

### 2.1 导航：11 个平铺入口，高频动作不在主路径

现状：

- 主导航是 11 个平级入口：仪表盘、持仓、台账、记一笔、导入、日历、对比、月报、年报、行情、设置（`ui/src/App.tsx:23`）。
- “交易记录”（撤销入口）放在设置里，而不是台账或战役详情里（`ui/src/App.tsx:166`、`ui/src/App.tsx:172`）。
- 从台账、日历或持仓点进战役详情后，返回按钮固定回仪表盘（`ui/src/App.tsx:163`），不回到来源页面。
- 台账筛选、报表年份、仪表盘搜索都是组件内状态；离开页面就重置。

为什么别扭：

用户的高频动作是“记一笔、看持仓、到期处理、对账、改错”。现在“导入”“行情”“日历”“对比”“月报”“年报”都占一级入口，而“改错”藏在设置最深处；从台账查一笔合约，看完详情回不到原来的筛选结果。

建议：

- 按任务分组：日常（仪表盘 / 持仓 / 记一笔）、账本（台账 / 交易记录 / 导入）、复盘（到期日历 / 报告 / 行情）、设置。
- “交易记录”并入台账，做成“台账 / 事件日志”两个页签；至少加标的、类型、日期筛选和金额列。
- 战役详情记住来源页，返回按钮回到来源并保留筛选。
- 到期日历可以并入“持仓”页签，减少一级入口。

### 2.2 修正：只能撤销，不能更正；撤销入口又在设置里

现状：

- 唯一修正手段是软删除，界面叫“撤销”（`crates/wheel-app/src/store.rs:588`、`ui/src/App.tsx:172`）。
- 撤销成功后提示“原始记录保留在审计日志中”（`ui/src/App.tsx:125`），但界面没有审计日志查看器；软删除事件不会出现在事件列表、CSV 或 JSON 导出中。
- 事件日志没有筛选、搜索、分页；费用 / 调整事件只显示“每股价格”和“费用”，真正的 `amount` 没有列（`ui/src/App.tsx:172`）。用户看不出这笔费用是多少。
- 撤销前会重校验后续事件，依赖关系不满足时直接拒绝；用户通常不知道该先撤哪一笔。

为什么别扭：

这是账本类软件最高频的“手滑”场景。错误可能只是价格少输一位、日期选错一天、费用漏填，但用户必须：找到设置 → 交易记录 → 在无筛选的长表里找到那一笔 → 撤销 → 回记一笔重录。若后面有平仓，还可能撤不掉。

建议：

- 把“交易记录”移出设置，放到台账页签，并在战役时间轴的每条事件上提供“更正 / 撤销”。
- 增加“更正向导”：明确告知会重算哪些后续事件；能安全重录的就原子地软删除 + 追加更正事件，不能的就解释依赖链。
- 事件日志增加标的 / 类型 / 日期筛选、金额列、软删除审计视图（只读）。
- 文案改为“原始记录保留在数据库中，当前界面不展示”，不要承诺一个不存在的审计日志页面。

### 2.3 日期：本地日期、UTC、美东三种基准

现状：

- 录入表单默认日期是本地日期：`today()` 使用 `new Date()` 的本地年月日（`ui/src/lib.ts:5`、`ui/src/EntryForm.tsx:7`）。
- 账本 `asOf`、收租月报、年度报表、备份时间使用 UTC（`crates/wheel-app/src/store.rs:402`；`ui/src/AnnualReport.tsx:76`、`ui/src/MonthlyIncome.tsx:84`）。
- 行情时间标注“美东”（`ui/src/MarketData.tsx` 的 `quoteTime`）。
- 页头同时写“UTC”，行情页写“美东”，行情页底部又写“本地时间”。

为什么别扭：

美股交易日期应按美东交易日理解。中国用户在凌晨 0:30（美东前一天中午）录入时，表单默认成中国日期，可能比真实交易日多一天；这笔交易会进入下一个月 / 下一年，`daysHeld` 也会多一天。反过来，中国晚上 22:00 录入时默认日期又和交易日期相同。用户很难自己判断什么时候该手动改。

建议：

- 定义一个产品级“交易日”概念：默认取 `America/New_York` 的当前日期作为录入日期；表单标签写“交易日（美东）”。
- 账本、月报、年报、战役起止、导入日期统一按这个交易日分组；备份 / 审计时间戳继续用 UTC，但要明确标“UTC 时间戳”，不要和交易日混用。
- 如果暂时不改模型，至少在录入页把“默认本地日期”和“报表按 UTC”写成显眼提示，并在保存前显示“这笔将计入 2026-11”。

### 2.4 录入：一个表单装十种交易，关键节点却是空白

现状：

- 一个表单承载卖出开仓、买入平仓、到期作废、指派 / 行权、买卖股票、分红、费用、调整、拆股（`ui/src/EntryForm.tsx:46`）。
- 分红只填“每股分红 × 股数”；不能在同一笔里填预扣税或券商费用，只能另记一笔“独立费用”。
- “独立费用”“现金调整”仍必须选标的，并计入该标的战役收支（`crates/wheel-app/src/commands.rs:1002`、`crates/wheel-app/src/commands.rs:1087`）。因此**没有账户级现金 / 入金 / 出金模型**；拿“现金调整”记入金会污染战役收益。
- 指派录入的 `cash` 计算没有分支（`ui/src/EntryForm.tsx:19`），现金净变化显示“—”；也不显示指派后新增 / 减少的股票、股数和成本。
- 战役详情只有 Call 指派预览（`crates/wheel-app/src/commands.rs:414`），没有 Put 指派预览。对车轮策略来说，Put 指派才是最常见的持股入口。
- 拆股表单只显示比例，不预览调整后的持股、未平仓行权价与乘数；保存后才知道结果。
- 滚动固定“同标的、方向与手数”（`ui/src/EntryForm.tsx:57`）；实际 roll 可能减手数、换方向或分批。
- 表单和导入向导都是组件内状态；切页、切换账户或关闭窗口会直接丢失未保存内容，没有草稿或离开确认。

为什么别扭：

“指派”是轮子从收租转为持股的关键一步，但当前界面在这一步提供的信息最少：不显示要付 / 收多少现金，不显示指派后的持股成本，也没有 Put 侧预览。拆股同样是高影响操作，却不给预览。用户只能保存后去仪表盘核对结果。

建议：

- 录入拆成三个模式：期权、股票、现金 / 调整。期权模式内部再按开仓 / 平仓 / 到期 / 指派切换。
- 指派表单增加预览：Put 显示“买入 N 股、现金流出 $X、指派后成本 A/B/C′”；Call 显示“卖出 N 股、现金流入 $X、剩余股数”。
- 增加 Put 指派场景预览，与现有 Call 预览对称。
- 拆股保存前预览：股数、行权价、乘数、零股补偿、现金变化。
- 增加 `cash_transfer`（入金 / 出金）事件，或明确声明本项目不管理账户现金；不要把入金记成 `adjustment`。
- 分红允许附带税费 / 费用，或提供“分红 + 预扣税”一次录入。
- 给录入表单和导入向导加草稿保存或离开确认。

### 2.5 导入：确认页只能改类型，批次不可撤销，费用去重有漏洞

现状：

- “逐行确认”只能改交易类型；日期、标的、数量、价格、费用、合约都是只读文本（`ui/src/ImportWizard.tsx:588`、`ui/src/ImportWizard.tsx:597`、`ui/src/ImportWizard.tsx:607`）。
- 设计文档写的是“可逐条改、可丢弃”（`DESIGN.md:731`），与实现不一致。
- 提交返回 `eventIds`，但没有批次 ID 或批次表；导入后无法整批撤销。备注前缀只有 `导入:<来源>`，同一来源的多次导入无法区分。
- 导入去重指纹包含账户、日期、类型、标的、到期、行权价、C/P、乘数、数量、价格、费用，但**不包含 `amount`**（`crates/wheel-app/src/import.rs:1324`）。费用和现金调整的 qty/price/fees 都是 0，因此同一天、同一标的两笔不同金额的费用会被判为重复。
- 同日多行按文件行号排序（`crates/wheel-app/src/commands.rs:1753`）；如果券商 CSV 是倒序，同一天的平仓 / 开仓可能被倒置。
- AI 截图选择文件后立即上传识别（`ui/src/ImportWizard.tsx:201`），没有单独的“确认上传”步骤；隐私提示在旁边，但不是上传前的门禁。

为什么别扭：

“逐行确认”给了用户一种可以修正的预期，但实际只能改类型。映射错了只能整批导入后再逐笔撤销；而费用去重漏洞会让用户以为第二笔费用是重复行，或者在允许重复后才发现两条记录金额不同却指纹相同。

建议：

- 确认页支持行内编辑日期、数量、价格、费用、合约、乘数；或提供“返回原始单元格修改后重新解析”。
- 为每次导入生成 `batchId`，在事件上记录批次；提供“撤销整批导入”，并显示批次导入时间、行数、来源。
- 指纹加入 `amount`（费用 / 调整至少加入），并给旧指纹做兼容迁移或双指纹匹配。
- 同日排序时提示“检测到同日多笔，请确认先平后开”；必要时让用户手动调整行序。
- AI 截图增加“确认上传并识别”按钮，显示将发送的图片缩略图和目标服务。

### 2.6 报表：四个页面都在说“收益”，口径不同

现状：

- 仪表盘“已落袋净收租”只含已了结期权净权利金（`ui/src/App.tsx:145`）。
- 收租月报“区间合计”= 净收租 + 分红 − 独立费用 + 现金调整（`ui/src/MonthlyIncome.tsx:92`）。
- 年度报表“年度合计”再加股票已实现盈亏（`ui/src/AnnualReport.tsx:85`、`ui/src/AnnualReport.tsx:124`）。
- 战役对比“已实现收益”按战役聚合，含分红、股票盈亏、调整（`ui/src/CampaignCompare.tsx:105`、`ui/src/CampaignCompare.tsx:126`）。
- 收租月报默认“全部年份”，年度报表默认最新年份；年度没有“全部年份”视图。
- 收租月报不含股票已实现盈亏，但名字像“收入总表”。

为什么别扭：

用户看到“已落袋净收租”“区间合计”“年度合计”“已实现收益”“本轮总收益”，很容易以为它们可以互相核对，实际口径和范围都不同。月底看月报、年底看年报时，同一年的数字对不上，会怀疑账本算错。

建议：

- 做一个“报告”入口，内部用页签：月度收入、年度已实现、战役对比。页面顶部固定一行“口径说明 + 统计范围 + 时间基准”。
- 统一命名：把“收租月报”改成“已实现收入月报”，把“年度报表”标注“含股票已实现盈亏”；“已实现收益”在战役对比里写明是否含费用 / 分红。
- 统一默认年份策略：要么都默认最新年份，要么都提供“全部年份”。
- 长期可以加一个“全部账户”汇总视图，但优先解决口径问题。

### 2.7 多账户：隔离彻底，但没有总览；账户级现金缺失

现状：

- 仪表盘、持仓、台账、事件、报表全部按当前账户隔离；没有“全部账户”视图。
- 行情与成本口径是全局设置（`README.md:28`、`ui/src/Accounts.tsx` 的说明）。
- 账户币种固定 USD；`insert_account` 直接写 `'USD'`（`crates/wheel-app/src/store.rs:361`），界面仍显示“币种”列。
- `broker` 字段存在于 schema，但创建账户时不采集。
- 归档账户从切换器隐藏；只有从未有过事件的账户可删除，撤销过全部交易也不能删。
- 最多 50 个账户（含归档），但没有在输入时显示剩余额度。

为什么别扭：

用户开多个账户（应税、退休、不同券商）后，最想知道的是“总 Put 资金义务、总未平仓权利金、总持仓”，现在只能逐个切换心算。账户币种列永远 USD，也让“多账户”看起来像支持多币种，实际不是。

建议：

- 增加只读“全部账户”仪表盘：总资金义务、总未平仓权利金、总持股、按账户拆分明细；写入仍回到单账户。
- 成本口径支持按账户覆盖，或明确写“全局口径会同时影响所有账户”。
- 删除币种列，或真正支持多币种；创建账户时采集 broker（可选）。
- 显示账户数量 / 剩余额度。
- 提供“清理账户”路径：允许在确认后清除无事件的已归档账户；有事件的账户只能归档。

### 2.8 提醒与行情：提醒只在你打开应用时存在

现状：

- 到期提醒只在应用内：侧栏徽标、仪表盘卡片、日历；没有系统通知或托盘常驻（`README.md:18`、`ui/src/Reminders.tsx`）。
- 持仓表显示“标的参考价”，但没有报价时间；只有战役卡片显示 `quoteTime`。
- 行情页的“账本行情”列表包含所有曾保存过报价的标的，价格全局存储且没有删除入口，列表只增不减。
- 自动刷新只覆盖进行中战役的标的，应用可见时每 5 分钟一次；其他已保存标的不会自动更新。
- 手动校准与同日自动报价的替换规则写在折叠区，容易被忽略。

为什么别扭：

一个“到期提醒”功能，如果必须打开应用才看得到，实际提醒价值有限。持仓页的价格没有时间戳，用户可能拿几天前的参考价做决策；行情列表里又会堆着已经不再交易的标的。

建议：

- 增加系统通知 / 托盘常驻（至少到期前 1 天、当天各一次），并允许关闭。
- 持仓表增加“报价时间 / 来源”列；过期报价用颜色或“已过期”标记。
- 行情列表允许移除标的价格记录；或只显示当前账户有事件的标的。
- 手动校准入口从折叠区提到正常位置，或在自动报价旁显示“同日手动校准会被自动更新覆盖”。

### 2.9 备份与恢复：安全，但不够可操作

现状：

- 备份列表只扫描数据库旁的 `backups/` 目录；校验和恢复只接受该目录下的文件名（`crates/wheel-app/src/backup.rs:74`、`crates/wheel-app/src/backup.rs:230`）。从别的机器拷来的备份，必须先手动复制进这个目录。
- 界面只显示数据库路径文本，没有“打开文件夹”按钮。
- 没有删除备份的入口；手动备份与 `pre-restore-*` 安全快照永远不会被自动清理。
- 恢复按钮写“确认恢复并重启”（`ui/src/SettingsData.tsx:197`），但实际只暂存，必须用户完全退出再手动启动。
- 暂存恢复期间所有写入被拒绝；没有“立即退出并重启”按钮。
- 桌面端没有单实例保护（`DESIGN.md:716`），同时开两个窗口可能造成误操作或写入竞争。
- 实时数据库是明文 SQLite；只有手动备份可选加密。

为什么别扭：

备份功能本身很稳，但“把备份从 U 盘恢复回来”这个真实场景，界面走不通；恢复按钮又承诺了一个它不会执行的“重启”。用户很容易在暂存后继续操作，发现全是只读，以为应用坏了。

建议：

- 备份页增加“从文件恢复”：选择任意 `.sqlite` / `.sqlite.enc`，复制到备份目录并校验；增加“打开备份文件夹”。
- 增加删除手动 / 安全快照的入口，二次确认；自动备份仍按保留数清理。
- 按钮改为“暂存恢复并退出”，如果平台允许，调用应用退出；否则明确写“暂存后请手动退出”。
- 加单实例插件；至少检测第二个实例并提示。
- 在首次使用清单中说明实时库未加密，建议开启 Windows 磁盘加密。

### 2.10 语言与细节

现状：

- 核心校验错误是英文，直接透传到界面：`symbol is required`、`price and fees must be finite and nonnegative` 等（`crates/wheel-app/src/commands.rs:1002`）。
- 安装器提供简体中文 / English，但应用界面没有 i18n，英文用户安装后仍是中文。
- 备份页版本兜底写死 `'0.3.0'`（`ui/src/SettingsData.tsx:131`），应用信息读取失败时会显示错误版本。
- 页头写 UTC，行情写美东，行情页底部写本地时间；三种时间词没有统一解释。

建议：

- 把常用后端错误映射成中文错误码 / 文案；至少覆盖录入、撤销、导入、账户、恢复。
- 安装器只保留简体中文，或真正做界面 i18n；不要给英文用户错误预期。
- 版本兜底改为 `—`。
- 在设置里增加“时间与日期说明”，统一解释交易日、行情时间、备份时间戳。

### 2.11 刻意取舍，不是缺陷

以下限制是有意为之，但应该在首次使用和空状态里写清楚，避免用户误解：

- 只支持卖出期权（wheel），不支持买入开仓、保护性 Put、价差、组合策略；导入会明确拒绝做多期权。
- 统一 USD，不做多币种换算。
- 不做券商连接、下单、自动同步；行情来自公开接口，可能延迟。
- 不做保证金、融资利息、税务申报；年度报表不是税务表。
- 不做自动更新、代码签名、崩溃上报。
- 不保留小数股；拆股零股用现金补偿。
- 一个标的在同一账户内只有一个进行中战役；同一标的多组并行轮子会被合并。
- 不做系统通知（目前）。

## 3. 建议顺序

**先做，不改领域模型：**

1. 统一“交易日”为美东，并改所有日期标签。
2. 导入指纹加入 `amount`；确认页支持行内编辑；增加批次 ID 与整批撤销。
3. 把交易记录移出台账 / 战役详情可撤销；事件日志显示金额、加筛选；修正“审计日志”文案。
4. 指派与拆股录入增加预览。
5. 修正恢复按钮文案、版本兜底、常见错误中文化。

**再做，需要小模型扩展：**

1. `cash_transfer` 入金 / 出金事件，或明确声明不管理现金。
2. 报告入口与统一口径说明。
3. 全部账户只读汇总。
4. 从文件恢复、打开备份文件夹、删除备份。
5. 系统通知 / 托盘、持仓报价时间。
6. 按账户成本口径。

**最后：**

1. 录入表单拆分为期权 / 股票 / 现金三种模式。
2. 单实例保护。
3. 界面 i18n 或移除英文安装选项。
4. 并行战役 / 多币种等更大的模型扩展。

## 4. 建议的验收场景

- 在中国时间 00:30 录入一笔美东前一天成交的平仓，确认它计入正确的美东交易日与月份。
- 从持仓页做一次同日 roll，确认平仓与新开仓按“先平后开”入账。
- 导入同一天、同一标的两笔金额不同的独立费用，确认不会被误判重复。
- 故意映射错 10 行并导入，确认可以整批撤销，而不是逐笔撤销。
- 部分指派一个 Put，确认录入页显示现金流出、新增股数与指派后成本。
- 2:1 拆股并填写零股补偿，保存前能看到调整后的持股、行权价与乘数。
- 从另一台机器复制一个备份文件，确认界面可以直接选择并恢复。
- 归档一个有交易的账户，再尝试删除；确认只能归档，且切换器隐藏。
- 撤销某账户全部交易后尝试删除；确认仍因审计记录被拒绝，并给出明确说明。
- 同时启动两个应用实例，确认有单实例提示而不是同时写库。

## 5. 结论

财务内核和边界处理已经足够可靠，下一阶段的设计关键词是四个词：**更正、对账、口径、总览**。

先把“记错了怎么改”“导入错了怎么退”“这笔到底算哪一天 / 哪个月”“多个账户总共多少”这四个问题解决，软件的“变扭感”会明显下降；表单拆分、多币种、系统通知都可以往后放。
